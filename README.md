# 宝宝信号 · Baby Signal

**把宝宝的哭声，变成照护人能看见、能感受到的提醒。**

面向听障妈妈及其他听障照护人的 iPhone + Apple Watch 开源工程原型。希望尽量使用家庭已有的设备，在手机本地识别哭声，再通过视觉状态和手腕触感提醒照护人。

> **当前重要限制：测试设备上，Apple 内置识别器锁屏后会中断。当前版本不适合依赖它进行夜间或无人看护监测。** 已有的编译、提醒测试和前台恢复成功，不能证明哭声检测可靠、后台整夜运行或一定唤醒照护人。我们选择把问题和失败记录一起开源，让后续改进有可复核的起点。

## 为什么做这个

起点是一段关于听障妈妈照顾孩子的视频，以及评论里提到的一个困难：听不到哭声的照护人，可能需要更频繁地用目光留意宝宝。

这个信息让发起人想到：很多提醒默认使用者能够听见。能不能把宝宝的声音转换成手腕上的提醒，让妈妈更容易获得信息，再由她亲自查看和照顾宝宝？

这段经历启发了项目，但我们没有独立核实视频涉及的个人情况，也没有与当事人合作或完成目标用户研究。公开资料不复制其头像、昵称、地点、聊天原句、病情或家庭信息。详细缘由见 [项目故事](docs/story.md)。

## 产品思路

**手机在宝宝附近 → 本地识别候选哭声 → 连续结果确认 → 系统提醒 → 配对手表提示 → 照护人查看宝宝 → 继续监测或快速恢复。**

- **尽量减少额外费用。** 第一版复用 iPhone 与配对 Apple Watch，不需要服务器；苹果设备并非人人拥有，未来欢迎更低成本设备的实现。
- **把感知入口做清楚。** 使用图片、简短文字、大按钮和触感提醒；不依赖声音或颜色单独表达状态。
- **保护家庭声音。** 不保存、不上传麦克风音频。事件和少量诊断只在手机本地保存。
- **由照护人判断。** 识别哭声只是提醒去看宝宝，不判断饥饿、疼痛、呼吸或疾病，也不代替照护。
- **显示真实状态。** 分析中断时明确提示检查；只有收到有效分析结果才显示恢复。停止一次提醒与停止整轮监测是不同操作。

架构、状态和后续方向见 [产品与技术思路](docs/product-design.md)。

## 当前实现和验证边界

| 能力 | 实现与证据 |
|---|---|
| 本地哭声分类 | 当前使用 Apple SoundAnalysis `baby_crying`；已知测试设备锁屏后失败，真实哭声闭环未通过 |
| 系统提醒及手表提示 | AlarmKit 已实现；一次测试闹钟由体验者确认手表震动，不代表每次送达或睡眠唤醒 |
| 灵动岛与锁屏卡片 | ActivityKit + WidgetKit 已实现；桌面状态已查看，锁屏卡片由体验者确认；不维持录音 |
| 自动与快速恢复 | 结束闹钟后尝试恢复；中断时可打开 App 一键重连；返回前台收到有效分析曾被验证，锁屏限制未解决 |
| 图解界面 | 三步插画、暖色界面、大按钮、系统字体缩放；VoiceOver 和完整大字体覆盖尚未完成 |
| 历史 CPU 实验 | 曾通过一轮锁屏系统测试闹钟恢复；现有短哭声样本未触发连续确认，不能作为准确率达标证据；不参与当前构建 |

**闹钟安排成功、闹钟触发、手表送达、照护人感知和睡眠唤醒必须分别验证。** 当前尚无准确率或可靠性承诺，也没有独立 watchOS App。

## 获取与安装

```bash
git clone https://github.com/zhangjianle0836-netizen/baby-signal.git
cd baby-signal
open BabySignal.xcodeproj
```

要求：Mac 与支持项目所需 iOS SDK 的 Xcode、iOS 26.0 或以上的 iPhone。当前工程在 Xcode 27.0 下构建；真机记录来自 iPhone 14 Pro / iOS 27.0.1。手表型号及版本由体验者提供为 Series 6 / watchOS 26.6，未独立读取完整手表版本。需要自己配对和验证提醒。

1. 在 Xcode 登录你自己的 Apple 开发账号。
2. 复制 `Config/Signing.local.xcconfig.example` 为 `Config/Signing.local.xcconfig`，填入自己的 Team ID。该文件不应提交。也可以在两个 target 的 Signing & Capabilities 中选择自己的团队。
3. 将 App 与扩展的 Bundle Identifier 改为你自己的唯一前缀，例如 `com.yourname.babysignal` 与 `com.yourname.babysignal.liveactivity`。扩展 ID 应以 App ID 为前缀。
4. 连接并解锁 iPhone，按 Xcode 提示完成信任和 Developer Mode；选择 `BabySignal` scheme 与实际设备，运行。
5. 允许所需麦克风与闹钟权限。先在宝宝休息区域外做“测试手表震动”，按提示锁屏，检查自己是否感到提醒。
6. “开始监测”只用于工程验证。当前已知锁屏中断；中断时打开 App 点“快速恢复监测”，待有效分析返回。

自用开发测试不需要上架 App Store。免费 Personal Team 通常需每 7 天重新签名安装；能力、签名及实际运行以你自己的设备验证为准。[苹果账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)

### 本机检查

```bash
./scripts/verify.sh tests                 # 逻辑、持久化、实际分类器静音输入
./scripts/verify.sh build                 # 无签名 iPhone 构建
./scripts/verify.sh all                   # 顺序执行测试和构建
./scripts/verify.sh device YOUR_DEVICE_ID # 自己的设备与签名配置，仅本地使用
```

脚本有单实例锁，最多 2 个构建任务。不要绕过活跃锁或并行运行多个验证命令。`.build`、签名本地配置、证书、设备日志及 Xcode 用户状态均不进入 Git。

已记录 65 项检查及 5 个真实内置分类器静音窗口通过；这些检查不等同于宝宝哭声识别准确。完整家庭场景检查见 [真机检查表](docs/device-test-checklist.md)。

## 最需要共同解决的事

1. 定位并解决锁屏分类失败：分别观察录音、分类与音频恢复，避免把引擎启动当成检测正常。
2. 验证系统级声音识别 + 快捷指令 + App 提醒动作的替代路径。它是待验证的方向，目前没有实现。
3. 用合法、匿名且独立的样本改进本地 CPU 检测，测量漏报、误报、端到端延迟与耗电。
4. 重复验证“锁屏哭声 → 手表提醒 → 停止提醒 → 下一轮检测”，然后才开展更长时间测试。
5. 与听障照护人共同验证交互理解、触感感知和无障碍，并探索便宜手机／手环的实现。

欢迎 [Fork](https://github.com/zhangjianle0836-netizen/baby-signal/fork)、提 Issue 或提交 PR。获取代码后可以按许可自行修改和再发布；改变识别器、触发规则或设备链路时，需要重新验证。[参与方式](CONTRIBUTING.md)

## 使用边界和隐私

当前是辅助照护的工程实验。没有检测到哭声不代表宝宝安全；不要为了测试故意让宝宝哭。手机及电线放在宝宝碰不到的位置，不放入婴儿床，不覆盖散热。测试时保留原有照护安排。

断电、退出、系统重启、崩溃、断连或权限改变时，App 可能无法主动通知。实时活动显示、一次手表震动及恢复按钮不能代替可靠性验证。

公开报告不要附真实宝宝照片／录音、聊天截图、健康信息、联系方式、位置、设备标识或签名资料。[隐私说明](docs/privacy.md)
