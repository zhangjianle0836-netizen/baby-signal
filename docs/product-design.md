# 产品与技术思路

**简体中文** · [English](product-design.en.md)

## 目标与范围

帮助听障照护人获得原本依赖声音的宝宝哭声信息，随后由照护人亲自查看。第一版目标是复用已有手机与手表，不增加服务器或云端音频上传。

本项目不识别哭声背后的医学或喂养原因，不诊断健康状态。当前真实哭声与锁屏闭环未达标，不能作为可靠照护设备使用。

## 信息流程

```mermaid
flowchart LR
  A[手机获取声音] --> B[本地声音分类]
  B --> C[连续确认和去重]
  C --> D[AlarmKit 系统提醒]
  D --> E[配对手表呈现提醒]
  E --> F[照护人查看宝宝]
  F --> G[结束一次提醒]
  G --> H[保持或尝试恢复监测]
  B --> I[真实状态更新]
  H --> I
  I --> J[手机 / 灵动岛 / 锁屏]
```

这是实现结构，不表示每一步已通过可靠性验收。手表是否收到、使用者是否感知，系统不能替我们作出确认。

## 当前组件

| 组件 | 职责 | 重要边界 |
|---|---|---|
| AVAudioEngine | 手机麦克风输入与生命周期 | 引擎启动不等于收到有效分类 |
| SoundAnalysis | 内置 `baby_crying` 候选结果 | 当前设备锁屏失败；计算设备不受 App 显式控制 |
| CryEventGate | 连续结果、安静重置与重复间隔 | 原型阈值不是准确率保证 |
| MonitoringRecovery | 保留用户意图、有限重试和恢复确认 | 不用重试假装已恢复；显式停止后不自动开麦 |
| AlarmKit | 安排、取消、观察系统闹钟 | 安排成功不证明手表已提醒或人已醒 |
| ActivityKit / WidgetKit | 显示状态、过期及打开 App 入口 | 不负责保活；系统调度可能延迟显示 |
| EventRepository | 最近事件及用户感知确认 | 不保存音频；记录可能包含使用时间信息 |

## 交互原则

- 图解与短文字并用，按钮足够大，状态不只依赖颜色和声音。
- “停止提醒”结束一次闹钟，“停止监测”结束整个声音检测会话。
- 中断时主操作是“快速恢复监测”；重连时保留同一位置显示等待。
- 只有新的有效分析结果返回，才显示继续监测。
- 过期或未知状态要求检查；没有哭声事件不表达宝宝安全。

## 后续路线，均需验证

**系统声音识别桥接实验。** 先单独验证 iPhone 辅助功能的宝宝哭声识别在锁屏下工作，再测试快捷指令声音触发、App Intent 和系统提醒链路。官方存在声音触发入口，整个产品链路尚未实现或验证。无法读取系统监听健康状态时，界面不能谎称掌握了实时监测状态。

**可控的本地模型。** 使用可以指定 CPU-only 的模型，验证输入采样、音频特征、分类输出和事件规则。现有 YAMNet 实验仅是起点；不能只靠降低阈值让单一测试片段通过。

**更低成本设备。** 研究可后台运行的手机加手环、局域网或其他触感提醒终端。先定义断连、耗电、权限与重复提醒的验收，再选择平台。

## 如何判断改进真的有用

分别记录录音是否继续、分类是否输出、事件是否生成、闹钟是否触发、手表是否到达、照护人是否感知、关闭后下一轮是否可用。使用独立合法样本测量漏报、误报、延迟与耗电，先白天验证，再在保留原照护安排的条件下验证更长时间。
