# 锁屏检测与闹钟停止后恢复

## 真机证据与修复

复测发现问题并非只发生在停止闹钟后：锁屏后 Apple 内置 SoundAnalysis 即出现 operationFailed（域 com.apple.SoundAnalysis、代码 2），重启音频会话又返回 560557684（四字符 !int）。确切的分类器内部原因没有从设备通用错误中取到，不声称已证实 GPU 错误；[苹果论坛的相似报告](https://developer.apple.com/forums/thread/811582) 也描述内置分类器在后台失败。

- 替换为明确 `MLModelConfiguration.computeUnits = .cpuOnly` 的 YAMNet 分类器；原始音频转换到 16 kHz mono，在原生代码中计算与 Google YAMNet 参数一致的 magnitude STFT／log-mel，输入 96 × 64。
- 使用 playAndRecord + mixWithOthers，避免后台恢复尝试抢占其他音频会话；真实电话／闹钟 alerting 状态仍不强行恢复。
- 有限重试耗尽后保留用户监测意图，暂停重试而非结束整个会话；新的闹钟结束或用户返回前台可重新尝试。
- 停止 Intent 容忍系统已移除闹钟的竞态；仍存在闹钟且 stop 失败时保留错误，不假装停止。
- 系统闹钟观察及每 3 秒状态检查发现 scheduled/alerting → absent 时通知恢复，不依赖一定观察到短暂响铃阶段。重复停止回调按 ID 去重。
- 提醒结束后先等待音频释放，再重启。真正收到有效分析后才显示恢复。显式停止或新进程启动不自动开启麦克风。

## 模型来源

[Yehor/YAMNet-CoreML](https://huggingface.co/Yehor/YAMNet-CoreML) 固定 revision 9681162a6618cceb548ee2a94e83bcfb3a141066，来源为 [Google YAMNet](https://github.com/tensorflow/models/tree/master/research/audioset/yamnet)，Apache 2.0。转换模型约 7.5 MB。固定文件 SHA-256 见 [yamnet-assets.json](yamnet-assets.json)。App 随附 Google 许可并在设置中提供来源与许可说明。不引入第三方运行时。

## 检查结果

67 项本机检查通过；包括恢复重试、闹钟结束重新给予恢复机会、显式停止不可被晚到回调覆盖、CPU 模型实际静音与音调预测、特征与独立 NumPy 参考比对、编码与活动过期等。真实旧 Apple 分类器的 5 个静音窗口也通过，但与 CPU 新模型分别计证。

外部短哭声样本出现 9 个 CPU 分析窗口，婴儿哭声最高约 0.463，仅一个窗口超过 0.30，连续确认未达成，未触发提醒。它不能作为整体准确率证据，而且是已知漏报示例。阈值为原型参数，需要独立、更多样本验证，尤其背景电视、说话、距离与不同婴儿哭声。

真机 CPU 新版：已签名构建安装。本轮测试闹钟已结束，约 2.3 秒后记录到有效分析恢复；随后快照为 monitoring、requested=true、attempts=0，分析时间持续更新。用户确认停止提醒后锁屏卡片显示“已恢复，继续监测中”。本轮锁屏与停止提醒恢复通过，不代表整夜稳定或所有中断场景已验证。用户随后确认解锁返回桌面时灵动岛显示“监测中”，电脑也已查看到相同显示。未验证真实婴儿事件的完整提醒闭环。

## 本地诊断

UserDefaults 保存最近 60 条错误／闹钟结束日志，以及 phase、用户意图、尝试次数、最近分析时间和快照时间；不录制或上传声音。Debug `--recovery-check` 仅在明确启动参数下开始验证，正常前台收到分析 8 秒后安排一个 15 秒测试闹钟。正常启动不触发测试。参数无持久化，每次操作需由开发人员明确调用。

## 电脑扬声器哭声复测

用户要求再次播放哭声并验证提醒与恢复。电脑将现有 `.build/audio-test/baby-cry.wav` 连续播放 3 次，约 15 秒，播放已正常结束。用户反馈未收到提醒。播放前后设备状态均为 monitoring、requested=true、attempts=0，最近分析时间推进，提醒记录没有新增哭声事件。

结果：本轮哭声提醒未触发，不能视为哭声检测闭环通过；也无法通过本轮验证哭声提醒停止后的恢复。此前成功的系统测试闹钟恢复验证仍成立，但不能替代真实哭声触发测试。当前没有保存逐窗口真机置信度，因此无法仅凭本轮确定是模型分数、扬声器／麦克风声学条件还是连续确认规则导致漏报。已知这段短样本离线只有一个窗口达到标准阈值，需重点排查。不要仅为让此样本触发而随意降低阈值或取消确认规则。
